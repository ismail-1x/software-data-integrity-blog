Software and Data Integrity Failures:

Integrity stays a part of CIA Triad that assure trustworthiness in the cyber world yet its complexity and risk of loosing it keeps evolving. Sometimes From even human mistakes and blind trust in elements for example third party applications or external libraries and dependencies that makes actors trust this code to be correct both now and, in the future, but some cases it wont be.

So what is Software and data integrity?

This term we are going to separate it into 2 parts:

Software integrity

It means the quality of the software’s source code and its essential to measure of how safe secure and reliable it is. We need to measure the maintainability and testability of the code so it’s comfort to the standards.

Data integrity

The property that data has not been altered, destroyed or lost in unauthorized manner. This assurance must hold true while data is either at rest in transit or actively in use.

But failures occur when some vulnerability left unpatched which allows external attackers to inject malicious updates of compromise the software

Who can be affected?

It compromises emails financial ledgers and reach to employees or customer information, this means businesses lose revenue and operational control.

Real-World Case Studies:

The SolarWinds Attacks: (year 2020)

The SolarWinds build system got compromised and attackers added backdoor to a legitimate software update.

More than 18000 organizations downloaded the malicious update allowing attackers deep access into internal systems for months.

SolarWinds partnered with CrowdStrike and KPMG to conduct a forensic cleanup and they had to build their assembly environment from scratch using a triple build architecture.

Source: Fortinet SolarWinds Cyber Attack

Event-Stream npm Package: year 2018

A malicious contributor added code to the popular event-stream npm package that targeted cryptocurrency wallets. Which impacted thousand of Node.js application.

The security team at npm immediately triaged the alert, permanently removed the malicious package from the public

Source: npm Details about the Event-Stream Incident

Codecov Bash Uploader Breach: year 2021

Attackers modified Codecov’s Bash uploader Script used in CI pipelines to leak environment variables containing credentials and tokens. A customer manually calculated and cross referenced the SHA checksum of the reference hansh and codecov’s github documentation.

they re secured their asset pipelines and legally advised impacted enterprises to immediately cycle all environment secrets

Source: Codecov April 2021 Post-Mortem

PREVENTION & MITIGATION

1- Use multi-factor Authentication MFA

Self explanatory the attackers if there is a breach would have one or more barriers to breach to grant them access to the system

2- Make sure you are using Code signing certificates

This like stamp of approval which ensure that the software cones from a trusted source basically digitally signing the code and provide a unique signature that verifies the authenticity of the software’s creator

3- Monitor for updates and security patches

Regularly monitor these updates and security patches to address potential vulnerabilities check for any bug fixes new features

4- Enforce Secure Code Reviews

It involves a thorough examination of each software component to identify the cyber threats that could compromise the application (CIA)

Implement a Software Supply Chain Security Program

Like OWASP CYCLONE DX OPEN VAS OPEN IAM they help find and mitigate vulnerabilities associated with open-source libraries framework or third-party software

5-Enforce CI/CD Pipeline Segregation & Access Control

A well-structured CI/CD pipeline ensures the code undergoes thorough testing and validation before being deployed into production it involves breaking down the development and deployment process into smaller manageable steps each with its own checks.

Source: Signmycode.com

CURRENT EVIDENCE & TRENDS

In the architectural mapping, A08: Software and Data Integrity Failures holds a permanent position as a core systemic risk.

OWASP split and expanded the overarching umbrella of code ecosystem risks. While A06 (Vulnerable and Outdated Components) focuses strictly on administrative neglect and unpatched legacy libraries, A03: Software Supply Chain Failures was established to address upstream infrastructure compromises.

The Distinction: This structural shift highlights that modern engineering teams face two separate problems: using known buggy software vs. attackers actively altering authentic code inside pipelines, registries, and updates to violate trust boundaries.
